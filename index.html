🏢 广东海圆圆农业科技有限公司 🧑‍💻 AI 全栈开发（实习） 🗓 2026.05 – 至今
项目概述

面向食材配送、食堂承包、团餐、农产品贸易企业的政府采购商机平台，把"找标—评标—跟标—复盘"这条高度依赖人工的经营流程，做成「采集 → 治理 → 分析 → 投标管理 → AI 决策」的自动化闭环。

业务痛点
  • 找标 · 漏标：公告分散在多个渠道且栏目列表有滚动窗口，人工刷站频率跟不上，中间公告说漏就漏。
  • 评标 · 报价无依据：报价是评分核心，却缺历史中标价与对手报价，只能凭经验拍板。
  • 跟标 · 跟踪混乱：澄清、更正、开标、废标等关联公告散在各人 Excel 与群消息里，交接容易丢失。
  • 复盘 · 数据不准：金额单位、时区、跨渠道重复公告口径不一，紧迫度与中标率统计失真。
核心功能
  • 01
    多链路采集引擎

    覆盖中国政府采购网、广东公共资源交易平台、AnySearch 三链路，适配器模式站点可插拔；水位增量采集 + 三级去重（URL 唯一 → 结构哈希 → 跨渠道相似度），重要标 2 小时级采集、列表窗口命中告警，从机制上防漏标。

  • 02
    数据质量闭环

    12 组预算正则 + 中文大写金额解析 + 元/万元换算三道脏数据防御，正则抽不到的字段交由 LLM 从正文补抽；入库前 XSS 清洗、双时区口径统一，配合误报 / 漏报校准反馈回路。

  • 03
    投标全生命周期跟踪

    一条公告 = 一个项目，9 态状态机（评估→准备→提交→开标→中标 / 履约 / 未中标 / 放弃 / 流标）+ 多责任人 + 事件时间线；自动关联澄清 / 中标 / 废标公告并推状态提醒。

  • 04
    AI 工作台（核心亮点）

    LangGraph + LLM 生产级 Agent，封装 46 个业务工具并落地五级安全分级授权，写操作走 interrupt() 审批、fail-closed；SSE 流式输出、对话内生成 ECharts、导出 Excel / PDF / Word；11 个飞书工具打通团队协作。

面向农产品分拣车间、对接企业 ERP 的称重 / 打印 / 扫码桌面应用，覆盖从称重到回传入库的完整闭环。

🏢 广东海圆圆农业科技有限公司 🧑‍💻 AI 全栈开发（实习） 🗓 2026.05 – 至今
项目概述

面向农产品（果蔬等）分拣车间的 WPF 桌面系统，把"称重 → 打印标签 → 回传 ERP → 确认入库"做成实时、可追溯、与 ERP 强一致的自动化流水线；.NET (C#) 双目标编译（net10.0-windows / net48）一套代码覆盖 Win10 与 Win7，日均处理订单行 2000+，10+ 台设备稳定运行。

业务痛点
  • 效率低：称重与录单割裂，原需 2 人 × 4 小时/天集中补录，一批完成才能录，时效差。
  • 易出错：手工抄录 + 二次录入，且单位常混用（销售按公斤、采购按斤），曾出现斤单回传 kg 记成一半的账面错误。
  • 设备杂：多台生产机多为锁死系统的 Win7（无法升级 .NET），电子秤有串口 / 蓝牙 / USB 键盘多型号，难以统一接入。
核心功能
  • 01
    多型号硬件接入

    IWeightReader / ILabelPrinter / IScanner 接口 + 工厂模式，接入串口 / BLE / HID 键盘楔入 / USB 四类设备；自研 ASCII 帧解析器一个入口兼容 3 种协议，触屏设置页免硬编码型号。

  • 02
    称重 → 打印闭环

    逐袋累重、手动输入与秤读数三级优先级；预览确认后驱动打印，17 字段可配字号 + 零依赖自绘 Code128（Code B/C 自动切换 + mod103 校验），标签扫码即可定位原订单。

  • 03
    ERP 回传与追溯

    称重回传 + 分拣确认 + 采购确认入库，销售 / 采购双数据源切换；失败自动入待重传队列、登录自动补传，杜绝"打印成功但 ERP 无数据"。

  • 04
    可靠性与部署

    打印前离线 / 暂停队列预检防"假成功"；DPAPI 加密本地存储；Inno Setup 安装包 + 双通道半自动更新（版本比对 + SHA256 校验）。

多平台热点聚合与 AI 分析平台 独立开发

👤 个人项目 🧑‍💻 全栈独立开发 🗓 2026.06 起
项目概述

面向网络内容创作者的热点情报系统，把"盯热榜—翻新闻—找选题—做分析"做成「采集 → 加工 → 分析 → 检索 → 推送」的自动化闭环。

业务痛点
  • 信息碎片：热榜分散在多个平台，官方新闻与热点话题割裂，来回切换耗时。
  • 只有榜单没有分析：原始榜单只是标题列表，趋势、情感、关键词和上升话题都要自己判断。
  • 缺乏创作闭环：除了看，还要能对话追问、找相似选题、导出报告、推送到飞书协作。
核心功能
  • 01
    多后端采集引擎

    微博 / 百度 / 抖音 / B站四个热榜 + 央视 / 凤凰网 / 联合早报 / 财新四个新闻源；「后端池 + 链式路由」7 类后端统一归一化输出，按数据源逐级降级、新增源零改代码；SPA 页用 Playwright 截获 XHR，请求自带签名天然绕过反爬。

  • 02
    成本递进的新闻漏斗

    7 级流水线（采集→硬过滤→去重→借热度→聚类→AI 精筛→入库），前四层纯免费规则（jieba 关键词、Jaccard 聚类、借热度打分），LLM 仅对候选集（cap 40）单次调用，无 API Key 时全链路规则兜底。

  • 03
    对话式 AI 工作台

    LangGraph + LLM 生产级 Agent，14 个业务工具 + 风险分级（read / confirm_write），写操作走 interrupt() 审批、fail-closed；token 级 SSE 流式输出、停止生成、中文感知上下文压缩控制成本。

  • 04
    语义检索与推送

    pgvector HNSW 索引 + 本地 bge-small-zh（512 维），采集流程自动增量嵌入，支持「找相似选题 / 历史事件复盘」；飞书 Card 2.0 交互卡片 + 机器人私聊对话中继。

Company Research 独立开发

输入公司名（可选行业词），自动生成行业调研报告（公司概况融入行业章节），Word 文档直接可用。

👤 个人项目 🧑‍💻 独立开发 🗓 2026.08
项目概述

面向投资研究、行业分析、企业 BD 尽调场景的自动化调研报告生产底座，把"搜资料 → 读资料 → 写报告 → 排版成 Word"做成一条自动化流水线，输出单份可交付的 .docx 10 章节行业研究报告。

业务痛点
  • 资料分散、采集成本高：在搜索结果页逐条点开→读→复制，年报 PDF 靠肉眼筛核心数据，人工耗时占全流程 60%+。
  • 来源不可靠、易断链：搜索 / 抓取 / 解析任一节点挂掉都要手工补，多源口径不齐需人工对齐事实。
  • 排版耗时：md 转 docx 的序号、列宽、目录页码、表头跨页重复等细节手工难以标准化。
核心功能
  • 01
    三级降级采集链

    搜索 anysearch 并行（章节级并发）→ firecrawl 兜底；抓取 crawl4ai 批量（domcontentloaded + 20s 超时）→ firecrawl → anysearch；PDF 用 markitdown 本地解析；抽取支持 firecrawl json schema 与本地 crawl4ai /llm。任一服务挂掉自动降级，全链路永不断流。

  • 02
    成本护栏 + 打分选源

    Budget 线程安全计数封顶并为"结构化抽取"预留 reserve 配额，遇 HTTP 402 立即毒化本次运行；按质量×相关性打分，无品牌信号的别家上市公司年报 -6 强降权，避免深抓配额被无关年报吃光。

  • 03
    双产物 + 缓存失效

    facts.md 兼容旧版，facts.json 附 stats 与 timing 供撰写阶段 LLM 判断可信度；磁盘缓存按 CACHE_VERSION + 查询 + 日期 24h TTL，版本变更即整体失效。

  • 04
    Word 专业化排版

    不只是 md 塞进 docx：TOC 域缓存章节列表（F9 刷新页码）、自动中文序号（一、/（一）/1./（1））、表头跨页重复、启发式列宽（每列 ≥2cm）、首行缩进 2 字符、页眉细线 + 页码从正文重排。

技术架构
Python 3.10+python-docxmarkitdown[pdf] anysearchcrawl4aifirecrawlDocker
量化成果
  • 报告生成从分析师手工 1-2 天压缩到 5-10 分钟（9 章节采集 + 撰写 + 排版一次完成）
  • 深抓提速两个数量级：8 页深抓从 12+ 分钟降到 1 分钟内
  • 报告排版 0 人工，输出可直接交付；即使 firecrawl 停用全链路仍可跑通
个人职责
  • 独立完成从架构设计到落地实现：4 层职责划分 + 13 个采集模块单一职责边界；成本护栏、三级降级链、打分选源、智能截断与文本清洗、品牌词提取、缓存失效。
