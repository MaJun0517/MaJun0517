# 农产品供应链招投标信息采集分析系统

> 面向企业招标团队的招投标信息采集、分析与投标管理平台，覆盖从数据采集到 AI 决策辅助的完整链路。

## 一、项目概述

面向**食材配送、食堂承包、团餐、农产品贸易**企业的政府采购商机平台。它把企业"找标—评标—跟标"这条高度依赖人工的经营流程，做成了一套「采集 → 治理 → 分析 → 投标管理 → AI 决策」的自动化闭环，解决企业在政府采购市场获客过程中"漏标、跟踪混乱、数据统计不准"三大痛点。

## 二、业务背景与痛点

企业招投标团队规模百人以上，其中折合约 **20 人全职投入"找标 + 跟标"**，此前靠人工刷政府采购网 + Excel 手工跟踪。按"找标 → 评标 → 跟标 → 复盘"这条真实链路拆开，每个环节各有两个绕不开的问题：

- **找标 · 发现商机**
  - **漏标**：公告分散在中国政府采购网、地方公共资源交易平台等多个渠道，栏目列表又有滚动窗口，人工刷站频率跟不上，中间的公告说漏就漏。
  - **筛选难**：每天新增公告成百上千，多数与本企业资质、经营范围、配送半径无关，靠人眼逐条翻，高价值食堂标被淹没在噪音里。
- **评标 · 该不该投**
  - **报价无依据**：报价是评分核心，却缺少历史中标价、竞争对手报价与预算区间做参考，只能凭经验拍板，报高失标、报低亏本。
  - **响应窗口短**：从公告发布到投标截止常不足 20 天，还要同步准备资质、报价、配送方案与保证金，判断慢一步就来不及。
- **跟标 · 流程推进**
  - **跟踪混乱**：一条标要经历澄清、更正、开标、中标结果、废标等关联公告，散落在各人的 Excel 与群消息里，交接容易丢失。
  - **节点易错过**：保证金缴纳、答疑提交、投标文件递交、开标多个时间点靠人记，错过一个就容易前功尽弃。
- **复盘 · 沉淀复用**
  - **数据不准**：预算单位（元 / 万元 / 大写金额）混乱、公告时间与服务器时间时区口径不一、跨渠道重复公告，导致紧迫度、今日新增、中标率等统计经常算错。
  - **经验无沉淀**：失标原因、竞争对手情报没有结构化沉淀，第二年同类标重复踩坑。

## 三、整体架构

- **前端**：Vue 3 + TypeScript + Element Plus + ECharts + Pinia
- **后端**：FastAPI + SQLAlchemy + Pydantic
- **数据**：PostgreSQL（Alembic 迁移）+ Redis（缓存 / 进度 / 限流）+ Celery（生产调度）
- **AI**：LangGraph + DeepSeek（fast / reason 双模型）
- **测试**：pytest（570+ 单测）+ Playwright E2E

架构图见同目录 `架构图.svg`。

## 四、核心功能模块

### 1. 多链路采集引擎

覆盖**中国政府采购网、广东公共资源交易平台、AnySearch** 三链路。采用适配器模式（Protocol + 注册表）实现站点可插拔；CCGP 支持"列表翻页 / 检索接口"双模式，列表抓满上限时自动降级检索补抓。通过**水位增量采集 + 三级去重**（URL 唯一 → 结构哈希 → 跨渠道相似度）实现采得全、存得净。反爬治理包括连接复用、检索会话预热、地区轮转游标持久化、±20% 抖动退避；重要标 2 小时高频采集，列表窗口命中自动告警，从机制上防漏标。

### 2. 数据质量闭环

字段抽取用**正则 + AI 双路**：12 组预算正则、中文大写金额解析、元→万元换算、三道脏数据防御（占位值 / 误标单位）；正则抽不到的字段由 DeepSeek 从正文补抽，`ai_enriched_at` 防重复。入库前统一 XSS 清洗（保留布局）、双时区口径统一（公告时间为北京时间墙上时钟、服务器时间为 UTC）。配合误报 / 漏报校准反馈回路，持续提升 precision / recall。

### 3. 可视化看板

统计卡片 + 趋势 / 分布 / 预算 / 紧迫度图表，双击钻取；Redis 缓存 5 分钟、采集入库后自动失效，大字段延迟加载保障查询性能。

### 4. 投标全生命周期跟踪

**一条公告 = 一个项目**，9 态状态机（评估→准备→提交→开标→中标/履约/未中标/放弃/流标）；多责任人、事件时间线；自动关联澄清 / 中标 / 废标公告并推状态 + 铃铛提示。

### 5. AI 工作台（核心亮点）

基于 LangGraph + DeepSeek 构建**生产级 Agent**：StateGraph 多节点工具循环 + PostgreSQL checkpoint 持久化会话与审批中断/恢复；封装 **46 个业务工具**并落地**五级安全分级授权**（read / auto_write / confirm_write / admin_confirm / 破坏性不注册），写操作走 `interrupt()` 审批、fail-closed；SSE 流式输出、渐进式工具暴露、中文感知上下文压缩控制成本；支持对话内生成 ECharts 图表、导出 Excel / PDF / Word 报告。

### 6. 飞书集成

11 个飞书工具（多维表格 / 云文档 / 日历 / 任务 / 消息）+ 机器人私聊即对话，写操作沿用同一套审批闭环，打通 AI 与团队协作。

### 7. 工程化与测试

570+ 单元测试 + Playwright E2E，含 AI 工具签名对齐、安全分级专项测试；Prometheus 监控指标、成本告警与采集滞后告警 Webhook。

## 五、量化成果

- 找标 / 跟标人力从 **20 人等效降至 8 人**（人力投入下降约 60%，人均产出提升至约 2.5 倍）
- 系统上线后累计自动采集 2400+ 条公告，重要标采集频率由人工日更提升至 2 小时级
- 后端 570+ 单元测试、前端 8 个 E2E 场景

## 六、个人职责

独立完成系统从 0 到 1 的全栈设计与开发；多次深入一线与投标专员沟通梳理真实流程，将痛点转化为需求并基于反馈持续迭代。
