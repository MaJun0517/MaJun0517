# 多平台热点聚合与 AI 分析平台

> 面向网络内容创作者的热点情报聚合与 AI 分析平台，覆盖从数据采集到对话式 AI 决策辅助的完整链路。

## 一、项目概述   https://github.com/MaJun0517/hot-topics

面向**网络内容创作者**的热点情报系统。它把创作者每天"盯热榜—翻新闻—找选题—做分析"这条高度依赖人工的流程，做成一套「采集 → 加工 → 分析 → 检索 → 推送」的自动化闭环，解决创作者在选题过程中"多平台信息碎片化、原始榜单无分析、缺乏创作辅助"三大痛点。

## 二、业务背景与痛点

内容创作者每天要盯着微博、百度、抖音、B站等多个平台的热榜，还要翻央视、凤凰网、联合早报、财新等权威新闻源找选题，信息非常碎片化。现有工具要么只覆盖单一平台，要么只有原始榜单没有分析，暴露三个核心问题：

- **信息碎片**：热榜分散在多个平台，官方新闻与热点话题割裂，来回切换耗时。
- **只有榜单没有分析**：原始榜单只是标题列表，创作者需要自己判断趋势、情感、关键词和上升话题。
- **缺乏创作闭环**：除了看，还要能对话追问、找相似选题、导出报告、推送到飞书协作。

## 三、整体架构

- **前端**：Vue 3 + Vite + Pinia + Vue Router（App Shell + 深色模式 + 多开窗口）
- **后端**：Django 6 + Django REST Framework
- **数据**：PostgreSQL 18（pgvector 向量索引）+ LangGraph checkpoint-postgres
- **采集**：后端池（Playwright / Crawl4AI / RSSHub / AnySearch 等 7 类后端）
- **AI**：LangGraph + DeepSeek（fast / reason 双模型）
- **语义**：sentence-transformers + bge-small-zh-v1.5（512 维）+ jieba

架构图见同目录 `架构图.svg`。

## 四、核心功能模块

### 1. 多后端采集引擎

覆盖微博、百度、抖音、B站四个热榜平台 + 央视、凤凰网、联合早报、财新四个官方新闻源。采用「后端池 + 链式路由」架构，7 类后端统一归一化输出，按数据源配置逐级降级，新增源零改代码；抖音/百度等 SPA 页用 Playwright intercept 截获 XHR（请求自带签名，天然绕过反爬，实测单源 51 条）；配限速抖动、指数退避、登录会话持久化、真实 UA 等反反爬治理。

### 2. 双模块数据体系

按平台分类分流为热榜模块（写 HotArticle，按热度排序）与新闻模块（写 NewsItem，按重要度排序），两套模型 / 索引 / 向量语义隔离；upsert + 下榜删除 + 热度快照（HeatSnapshot），支持上升话题识别。

### 3. 成本递进的新闻漏斗

7 级流水线（采集→硬过滤→去重→借热度→聚类→AI 精筛→入库），前四层纯免费规则（jieba 关键词、Jaccard 聚类、借热度打分），LLM 仅对候选集（cap 40）单次调用，无 API Key 时全链路规则兜底，自动产出每日要闻。

### 4. 对话式 AI 工作台（核心亮点）

基于 LangGraph + DeepSeek 构建生产级 Agent：StateGraph 多节点工具循环 + PostgreSQL checkpoint 持久化会话与审批中断/恢复；封装 14 个业务工具并落地风险分级（read / confirm_write），写操作走 interrupt() 审批、fail-closed；token 级 SSE 流式输出、停止生成、中文感知上下文压缩控制成本；支持对话内生成 ECharts 图表、导出 Excel 报告。

### 5. 语义检索

pgvector HNSW 索引 + 本地 bge-small-zh 模型（512 维），采集流程自动增量嵌入，支持「找相似选题 / 历史事件复盘」。

### 6. 飞书集成

直连 OpenAPI 推送 Card 2.0 交互卡片（热点速报 + 每日要闻）+ 机器人私聊对话中继，打通 AI 与团队协作。

## 五、量化成果

- 聚合 597 条实时数据（251 条热榜 + 346 条新闻），跨平台热度总量级超亿
- 24 个采集源健康度全绿，抖音单源 Playwright 实测抓取 51 条
- 语义检索向量覆盖率 100%，「找相似选题」功能真实可用
- 语义检索 / AI 分析 / 采集均具备优雅降级，无 API Key 或后端失败不中断主流程
