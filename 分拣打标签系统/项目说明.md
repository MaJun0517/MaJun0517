# 分拣打标签系统

> 面向农产品分拣车间、对接企业 ERP 的称重 / 打印 / 扫码桌面应用，覆盖从称重到回传入库的完整闭环。

## 一、项目概述

面向农产品（果蔬等）分拣车间的 WPF 桌面系统，把"称重 → 打印标签 → 回传 ERP → 确认入库"这条原本高度依赖人工的流程，做成了一条实时、可追溯、与 ERP 强一致的自动化流水线。系统以 .NET (C#) + WPF 开发，采用 `net10.0-windows` / `.NET Framework 4.8` 双目标编译，一套代码同时覆盖 Win10 与 Win7 生产机；日均处理订单行 2000+，10+ 台生产设备稳定运行。

## 二、业务背景与痛点

分拣车间原流程为：工人按订单称重 → 手写记录 → 等一批订单完成后由专人集中录入 ERP。这套流程暴露四个核心问题：

- **效率低**：称重与录单割裂，称重靠人、录单靠专人（原需 2 人 × 4 小时/天），一批完成后才能补录，时效差。
- **易出错**：手工抄录 + 二次录入，且单位常混用（销售按公斤、采购按斤），曾出现"采购斤单回传 kg 记成实际一半"的账面错误。
- **难追溯**：标签无统一编码，出库后无法反查是哪一单、哪一批。
- **设备旧、硬件杂**：多台生产机多为锁死系统的 Win7（无法升级 .NET 10），电子秤又有串口、蓝牙、USB 键盘等多种型号，难以统一接入。

## 三、整体架构

- **界面**：WPF，全屏登录门禁页 + 主界面（2×2 任务卡片）+ 触屏设置弹窗
- **多目标**：`net10.0-windows`（Win10+，含 BLE）/ `net48`（Win7 兼容，无 BLE），同一套代码条件编译
- **硬件抽象**：`IWeightReader` / `ILabelPrinter` / `IScanner` 接口 + 工厂模式，接入串口 / BLE / HID 键盘楔入 / USB 手动四类电子秤与标签打印机
- **打印**：XPS 驱动打印 + 零依赖自绘 Code128 条码 + 17 字段可配字号模板
- **存储**：DPAPI 加密本地存储（会话 / 凭据 / 待重传队列 / 设备历史）
- **部署**：Inno Setup 安装包 + 双通道半自动更新（版本比对 + SHA256 校验）

架构图见同目录 `架构图.svg`。

## 四、核心功能模块

### 1. 称重采集
接入四类电子秤，自研 ASCII 帧解析器一个入口兼容 3 种协议（首衡 / TWI / 通用数字帧）；支持手动输入、逐袋累重，重量优先级"手动 > 累重 > 秤读数"。

### 2. 打印标签
预览确认 → 驱动打印；17 个字段每字段可自定义字号；自绘 Code128 条形码（Code B/C 自动切换 + mod103 校验），标签扫码即可定位原订单；支持已分拣订单补打。

### 3. 扫码追溯
物理扫码枪（键盘楔入、免探测）自动输入定位订单，与标签条码形成"打印 → 扫码 → 反查"闭环。

### 4. ERP 回传
称重回传 + 分拣确认 + 采购确认入库，销售 / 采购双数据源切换；失败自动入待重传队列、登录自动补传，杜绝"打印成功但 ERP 无数据"。

### 5. 硬件配置
四标签触屏设置页，探测并选择设备（免硬编码型号），串口参数 / 打印模板 / 小数位 / 明暗主题均可配。

### 6. 可靠性与部署
打印前离线 / 暂停队列预检防"假成功"；DPAPI 加密凭据；双通道半自动更新（客户端点几下完成升级）。

## 五、量化成果

- **录单岗位归零**：原 2 人 × 4 小时/天集中录单 → 实时自动回传，全年省人力约 **7.2 万元**。
- **单票提速 10 秒**：日均 2000 单，每天省约 5.6 人时。
- **全年合计测算节省约 14.2 万元**（提效 12.2 万 + 防损 2.0 万），折算每天 14.8 人时 ≈ **1.9 个全职岗位**。
- **错单防损**：自动采集 + 多单位换算 + 回传补偿，每避免 1 笔错单减损约 **330 元**（含 6 人时处理人工）。

## 六、个人职责

独立完成系统从 0 到 1 的设计与开发，覆盖需求调研、开发、测试到现场部署全流程；多次深入一线与工人沟通，把操作习惯直接转译成交互设计（免探测扫码、累重动作按钮、触屏大按钮），系统落地即用、培训成本极低。
